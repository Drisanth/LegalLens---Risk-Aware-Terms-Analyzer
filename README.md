# LegalLens – Risk-Aware Terms Analyzer

LegalLens is a privacy-first, risk-aware legal document analyzer that uses a novel risk propagation engine to identify, quantify, and visualize liabilities in complex contracts.

## 🚀 System Architecture

### Pipeline Overview
1.  **Input Layer**:
    *   Chrome Extension (Manifest V3) for real-time web analysis.
    *   Web Dashboard for document upload (.pdf, .txt).
2.  **Preprocessing**:
    *   Clause Segmentation: Heuristic + NLP splitting.
    *   Embedding Layer: `distilbert-base-uncased` (Singleton, FP16 optimized).
3.  **Risk Analysis Core (The Patentable Engine)**:
    *   **Base Risk Scoring**: Keyword + Zero-shot classification.
    *   **Dependency Graph**: NetworkX graph where Nodes=Clauses, Edges=Semantic Similarity.
    *   **Risk Propagation**: Recursive algorithm diffusing risk from high-liability nodes to dependent clauses.
    *   **Personalization**: Weighting based on user sensitivity profile.
4.  **Output Layer**:
    *   Interactive Heatmap & Force-Directed Graph.
    *   Risk-Prioritized Summarization (DistilBART).
    *   Explainability (Attention-based token highlighting).

*API runs at http://localhost:8000*

### 2. Frontend Setup
```bash
cd legal_lens/frontend
npm install
npm run dev
```
*Dashboard runs at http://localhost:5173*

### 3. Chrome Extension Setup
1.  Open Chrome and navigate to `chrome://extensions/`.
2.  Enable **Developer mode** (top right).
3.  Click **Load unpacked**.
4.  Select the `legal_lens/extension` directory.
5.  Pin the extension and visit any Terms & Conditions page to analyze.

## 📄 Patent Documentation

### Title
**SYSTEM AND METHOD FOR RISK PROPAGATION AND CONTEXT-AWARE ANALYSIS IN UNSTRUCTURED LEGAL TEXTS**

### Abstract
A system for automated legal risk analysis that utilizes a semantic dependency graph to propagate risk scores across interrelated clauses. Unlike traditional keyword-based approaches, this invention constructs a weighted graph of legal clauses based on semantic embedding similarity and propagates risk values using a damping factor, identifying "hidden" risks in seemingly benign clauses that depend on high-liability sections. The system further includes a user-configurable personalization layer and an attention-based explainability module.

### Mathematical Formulation
The core risk propagation is defined by the iterative update rule:

$$ R_{new}(i) = R_{base}(i) + \alpha \sum_{j \in Neighbors(i)} (W_{ij} \cdot R(j)) $$

Where:
*   $R(i)$ is the risk score of clause $i$.
*   $\alpha$ is the propagation decay factor (configurable, default 0.3).
*   $W_{ij}$ is the cosine similarity weight between clause $i$ and $j$.
*   $R_{base}$ is the initial inherent risk score derived from classification.

Personalization is applied as:
$$ R_{final}(i) = R_{propagated}(i) \cdot (1 + \beta \cdot U_{weights}) \cdot S_{user} $$

### Claims

**Claim 1 (Independent):**
A computer-implemented method for analyzing risk in legal documents, comprising:
(a) segmenting a text document into a plurality of discrete local clauses;
(b) generating a semantic embedding vector for each clause using a transformer-based language model;
(c) calculating a base risk score for each clause based on risk category classification;
(d) constructing a dependency graph where nodes represent clauses and edges represent semantic similarity exceeding a predetermined threshold; and
(e) executing a risk propagation process where risk values flow across edges to iteratively update clause risk scores, thereby identifying indirect risks.

**Claim 2 (Dependent):**
The method of Claim 1, wherein the risk propagation process utilizes a damping factor $\alpha$ to prevent infinite feedback loops.

**Claim 3 (Dependent):**
The method of Claim 1, further comprising a personalization step wherein risk scores are dynamically re-weighted based on a user-defined sensitivity profile and specific category weights.

**Claim 4 (Independent):**
A non-transitory computer-readable medium storing instructions that, when executed, cause a processor to render a graphical user interface displaying:
(a) a force-directed graph visualization of the clause dependency network;
(b) a heat map overlay indicating risk intensity; and
(c) a prioritized summary generated by identifying and aggregating clauses with propagated risk scores above a specific threshold.

**Claim 5 (Dependent):**
The medium of Claim 4, where the system utilizes an attention-mechanism to extract and highlight specific tokens within a clause that contribute most significantly to the assigned risk score.

**Claim 6 (Dependent):**
The system of Claim 1, configured to load the embedding model as a singleton instance to minimize memory footprint during batched processing.

**Claim 7 (Dependent):**
The method of Claim 1, wherein the input text is acquired via a browser extension injecting a content script into a web page to extract renderable text.

**Claim 8 (Dependent):**
The method of Claim 1, comprising a hybrid execution mode that automatically selects CUDA acceleration if available, and falls back to CPU processing otherwise.
